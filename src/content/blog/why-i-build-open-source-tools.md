## Small Tools Compound

The best open-source tools often begin as repeated friction. A command is too manual, an integration has no obvious package, or a project needs the same adapter for the third time.

I build these tools because every solved piece becomes leverage for the next project. The package is not just code; it is a note to future me and a shortcut for someone else.

## Public Work Improves the Work

Working in public forces clarity. The README has to explain the intent. The examples have to be honest. The API has to survive another developer seeing it without the private context in my head.

That pressure is useful. It makes the work kinder.
